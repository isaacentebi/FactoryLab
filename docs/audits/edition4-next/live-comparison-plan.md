# Fresh control and consequence comparison

Source release: `a4e022622894d9064fdc26e840c08be52344202b4569be24a2f52d8eec13bd2a`.
Both arms use the repaired interface, full unchanged norms and roster, reference
prompt mode, and the same fixed horizons. The only manifest difference is
`evaluation.producer_feedback`: `verdict` versus `realized`. No new institution,
activity target, model selection rule or reasoning disablement is introduced.

Run control first, then consequence, **30 minutes and at most USD 3 inference
each**. The existing runner gives each a fresh testnet client namespace, a
declared 10-second tick, prepaid inference only, and no treasury transfer,
top-up or x402 purchase. The USD 50 cumulative authorization includes these caps
and the earlier probes. Actual delivered tempo must be reported; dispatch is
serial. This is a screening pair, not a randomized causal estimate.

The shared testnet account is a confound: record equity, positions and orders
before and after each arm. Do not treat a new namespace as a new account or
pretend the venue contains the manifest's nominal capital. Stop before the next
arm if the prior arm leaves positions/orders or any uncertain bill requiring
reconciliation. No manual intervention in a running world; its diary is read
only after the bounded runner ends it. The rehearsal observer may expose its
existing permitted aggregates while it runs.

Predictions and assessment:

- Valid tool invocations are now feasible; the paid interface probe establishes
  that. It does not predict voluntary use. Report attempted, accepted, executed
  and receipt-informed work separately.
- Consequence mode must feed only grounded final findings into producer
  learning. Initial verdicts alone must not train it. Report how many decisions
  reach valid observed support/contradiction and how many remain unknown.
- Seek at least ten grounded assessments with eligible evidence, including an
  observed contrary case. Fewer is an inconclusive screening result, not a
  reason to relabel missing evidence or extend a running world's parameters.
- Declining may remain prevalent. More messages, trades, program executions or
  favorable scores alone do not establish useful cooperation or autonomy.
- An income-to-inference loop is not testable as real income in this prepaid,
  testnet-only comparison. Do not count testnet P&L as independent real revenue.

Hold the combined P+A+C versus P experiment until these results can be read.
This comparison does not authorize a mainnet or funded-world launch.

## Audit decision while control was running

The independent Astra audit found that the final consequence judge's emitted
evidence is omitted from its standard meta request and that grounded completion
bypasses the ordinary verdict commitment. The lead confirmed both source paths.
The control is allowed to finish unchanged. The paid consequence arm is deferred
until a focused production-route reproduction and repair of this gap; it has
not been run. This avoids treating producer feedback alone as a closed recursive
learning loop. If the source changes, a future matched pair needs a fresh control
on that source rather than silently reusing this control as equivalent.
