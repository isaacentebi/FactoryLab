# Investigation interface experiment

Authorized after PR114: replay failed investigations, compare a lean request with
current requests on identical commissioned cases, then run a matched population
pilot if the interface works. No new objective, reward, role or institution is
introduced. No mainnet, top-ups, fund transfers, or access to a living diary.

## Controls

Baseline code is c0b29e6dfbeb66f90ade82eec2840b13c1fcdc11 (including the explicit
schema-derived batch-limit instruction). Candidate changes only compact context
presentation and its exact retrieval routes. Both arms use the declared R2
OpenRouter roster from work/coverage-60-r2/world.toml, unchanged low reasoning,
output allowances, norms, charter, endowments, tools and consequence horizons.
Reference-mode prompts remain available but are not this experiment's baseline:
the comparison is previous compact versus lean compact.

## Offline before spend

Replay actual rejected R2 tool batches through validation. Demonstrate the
corrected bounded sequence through the real runtime on a fake venue: schema
lookup, execution, returned evidence, further lookup and final decision within
one handle and its paid reservation. Authored corrections are diagnostic inputs,
not claims that the population corrected itself.

Verify every omitted context field remains exactly retrievable, the fixed norms
remain inline, the immediate task and full outcome schema remain unchanged, and
operating context does not enter frozen judging evidence. Measure request sections
and bytes on identical fixtures; do not substitute a character ceiling for cost.

## Small real-model comparison

Two current models (GLM 5.3 Flash and Luna), two commissioned tasks, two source
versions: eight decisions in total, with their actual continuations. The tasks are
a discoverable calculation and six exact private outcome facts that require
bounded retrieval batches. Use a fake exchange and deny all external action rails.
Record discovery separately; do not require a needless schema lookup if a model
already has the exact usable contract. Score success from executed tool receipts
and the final exact answer, not a claim to have investigated.

The $1 total admission reserve is split equally across source arms. Each arm
permits at most 40 provider calls, with no automatic retries or silent fallbacks.
Initial requests must match preflight hashes at actual dispatch; continuations
are logged. Preserve raw request/answer evidence privately and publish only safe
aggregates. Any ambiguous bill stops further paid probes and retains its ceiling.

Candidate progression requires all four model/task chains to complete, no
per-model regression against baseline, exact recoverability, and a reduction in
median input tokens. Report total cost per successful chain, including failed
calls and retrieval overhead. Four cases are a mechanical screen, not a statistical
estimate of reliability. A failed candidate returns to offline diagnosis; do not
launch a population run to diagnose a reproducible interface failure.

## Population pilot, conditional on the screen

Run two fresh 60-tick worlds sequentially: previous compact first, lean compact
second, using frozen source trees. Each gets a 60-minute deadline, $1.50 admission
cap and 300 calls. Use the same seed/roster/settings, realized feedback and voluntary
addressing. No observer; inspect only after terminal sealing. Confirm flat venue
state before the next arm. Reserve both caps in the cumulative $50 ledger before
dispatch, and reconcile actual bills and venue state afterward.

This matches the declared controls, not external market paths or model sampling.
Treat it as a descriptive pilot; do not attribute a trade or cooperation rate to
context alone. Keep the existing screen (60 ticks, ten assessed grounded findings,
one contrary finding, all authoritative bills), with no post-hoc extension.

Primary observations: investigations attempted/rejected/executed; evidence fetched
and actually supplied to a continuation; later decisions after retrieved contrary
feedback; and another participant's use of a produced artifact. Distinguish exact
retrieval from acknowledgement. Report hold/defer choices, malformed outputs,
costs, context tokens and latency separately. No activity is rewarded merely for
appearing. A successful interface with continued passivity is evidence about the
population, not a reason to manufacture demand or cooperation.

## Corrected screen, declared before its dispatch

The first comparison spent $0.022129, but its custom task schemas omitted the
numeric tool-batch bound from the initial request. They required discovery of the
return-envelope limit as well as the task's tool schema. This confounds the
intended retrieval screen; preserve its failures and bills, but do not use it to
infer that models ignored a visible limit or that a native-tool redesign is
necessary.

The corrected diagnostic composes the same authoritative optional tool-call
schema into both arms' task contracts. Offline assertions must establish that
all eight initial requests show the manifest's actual numeric limit and preserve
the same final-answer requirements. The candidate also publishes that bound in
its general capability index for arbitrary task schemas. No batch is split or
executed automatically and no returned fact is invented.

Run each corrected arm once with a $0.48 cap, keeping the original tasks, models,
settings, fake venue, and denial rules. Together with the earlier spend this can
cost at most $0.982129, still below the original $1 total. Retain separate frozen
sources, preflights, and captures. The progression criteria remain all four
candidate chains successful, no per-model regression, exact retrieval, and lower
median input tokens. A further failure stops the population pilot; there is no
paid retry of an unchanged corrected fixture.


Before corrected dispatch, a prompt-derived offline responder exposed a second
mechanical limitation: after a 4+2 read sequence it saw only 2 facts, then 4 on
reread, then 2 again. Intermediate model answers and their private working_state
were absent. A canned answer with fixture-known facts had concealed this.

The candidate therefore also extends the existing working_state contract: a
valid paid intermediate note commits through the existing owned, metered state
store and is visible to the next continuation. A later failed final answer does
not undo that earlier paid write. The corrected commission explicitly permits
private state and forbids public writes or external actions. Its scripted final
answer must be derived only from facts in the actual rendered prompt, including
the model's own carried notes. No aggregate facts are supplied by the kernel.

The corrected candidate is a bundle of exact context retrieval, explicit batch
contracts, and intermediate private memory. Paid results cannot isolate these
components. Offline regressions isolate their mechanical effects. The old
comparison is retained as confounded diagnostic evidence, not a model ranking.
